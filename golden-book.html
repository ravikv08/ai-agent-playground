00How to Use This Book

This is a path, not a pile of links. Each chapter has a goal, a "you can now…" outcome, a short ordered reading/watching list (⭐ = the must-do spine), and a hands-on build. Go in order; the chapters compound. You can go from total beginner to someone who architects enterprise multi-agent systems by walking straight down it.

Four rules

1 · In order. Each chapter assumes the last. Skipping foundations is why demos die in production.

2 · Build at every chapter. Watching ≠ learning. Ship the tiny project each time.

3 · The ⭐ spine first. Do the starred items, then circle back for depth.

4 · Evals are the golden skill (Ch IV). Anyone can demo an agent. Knowing it's good — and catching when it breaks — is the craft. The whole book bends toward it.

The one law of this bookEvaluation-driven development. You don't improve an agent by vibes — you improve it against a dataset, with experiments that act as gates for shipping. Collect feedback → add to a golden dataset → run the experiment → only ship if it passes. Internalize this loop (Chapter IV draws it) and everything else falls into place.

Chapter IV · Strengthen · ★ the heart of the book

IVEvaluate — The Golden Skill

Goal: measure quality instead of guessing. Build datasets, trace runs, grade with code + LLM-judge, and gate every change. This is what separates engineers from demo-builders.

✓ You can now prove whether a change made your agent better or worse, trace any run, and gate shipping on experiments.
"The agent that produces a result should never be the only thing that judges it. Build the dataset, run the experiment, let it gate the ship."— evaluation-driven development, the law of this book

◆The Capstone

One project ties the whole book together. Build it and you've proven every chapter:

Build an evaluation-driven production agent. Pick a real task (support resolution, research assistant, a coding helper). Then:

① give it tools + RAG (Ch II) · ② harness it for multi-step work (Ch III) · ③ trace it and build a golden dataset + LLM judge (Ch IV) · ④ deploy it with guardrails and a cost dashboard (Ch V) · ⑤ write its enterprise solution design (Ch VI) · ⑥ benchmark it and read one frontier paper that could improve it (Ch VII).

Gate every change on the eval suite. When a change can't ship because it drops the score — you've arrived.

Courses teach the parts. Building teaches the whole. Walk the seven chapters in order, ship the capstone, and you won't just understand agents — you'll architect them.— The Agent Golden Book
